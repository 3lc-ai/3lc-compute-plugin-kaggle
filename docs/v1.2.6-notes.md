# v1.2.6 — release notes + tester note (drafts; tag pending PRETAG_1.2.6.md)

## Release notes

v1.2.6 replaces the per-tab copies of shared workflow state with one
canonical **session object**. The project name, table name, dataset yaml,
device, and competition-slug decision now live under a single `session` key
in `ui_config.json`; tabs render projections of it, table URLs are derived
rather than stored (explicit per-field overrides excepted), and a one-shot
migration folds existing configs in. This closes the round-2 orphaned-run
bug (DP-01) and its whole class: DP-02, DP-04, DP-05, DP-06, DP-08, DP-09,
DP-10 in the state audit's numbering.

**Deliberate behavior change:** training a Run into a different project
than its tables is **no longer expressible in the UI**. The Train tab's
Project field is gone; the run's project is the session project — the one
Import created the tables in — rendered as a read-only fact. For this
competition that freedom was exactly the bug (a Run orphaned from its data
breaks the fix-labels → retrain Loop). The project remains editable on the
Import tab; anything that genuinely needs a run parked elsewhere (e.g.
control-sanity runs) already bypasses the UI.

Also in this release: the competition slug tracks the shipped default
unless deliberately overridden (a future slug change reaches every install
that never chose its own); table-name changes now flow into the derived
Train/Predict URLs; the page sequences its initial load so a slow worker
costs latency, never state; and a pytest layer (dev-only dependency,
never shipped) pins the migration against two real-world configs.

## Tester note (Teams draft)

v1.2.6 is available. Two things to know before/after updating, then it's
the normal flow:

1. **Hard-refresh the plugin page after updating** (Ctrl+Shift+R, or
   Cmd+Shift+R on Mac). Your browser may keep the old page cached, and the
   old page saves settings in a format v1.2.6 deliberately rejects — the
   symptom is that nothing you type on the page survives a reload (saves
   fail silently in the background; your training runs and data are
   unaffected). One hard refresh fixes it for good.

2. **Check your table URLs once after updating.** Settings move into a new
   one-project session layout on first load. If you ever hand-pasted a
   table URL pointing at a *different* project than your import, that URL
   is cleared by design (it was the source of the orphaned-run bug) — the
   fields re-fill with the right tables for your project automatically.
   Revision choices *within* your project (e.g. a fixed-labels revision
   picked in the revision picker) are preserved.

You'll also notice the Train tab no longer has a Project field: runs now
always land in the same project as your imported tables (that's the
orphaned-run fix). The project is set on the Import tab.
