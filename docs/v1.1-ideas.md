  - **Wheel-source distribution risk — RESOLVED for v1.2.8, was a
    landmine at v1.2.7** (added 2026-08-31; names the risk on the Q1
    wheel option for public distribution). Mechanism, watched: uv honors
    a **git source's own `[tool.uv]` indexes**, so the catalog's git
    source kept resolving even with dead pins — the retired prereleases
    index silently carried SDK 0.1.1 into every install. **A wheel
    carries no `[tool.uv]`** (by construction — verified in the built
    1.2.8 wheel's METADATA), so a wheel-source catalog resolves from
    the host's configured indexes alone; on modern hosts that is
    **public PyPI only**. At v1.2.7 that failed hard ("only
    3lc-compute-plugin-sdk[shared]>=0.2.2 is available" — watched,
    --no-cache, PyPI-only). **Mitigation, now the standing rule:
    whatever we publish must resolve from public PyPI alone with no
    index configuration.** Verified for v1.2.8 (2026-08-31, Windows /
    py3.12): built the wheel, dry-run installed
    `wheel[kaggle]` into a clean venv with `--no-cache
    --index-url pypi.org` → **full resolution, 113 packages** (SDK
    0.3.2, 3lc 3.3.0, 3lc-ultralytics 0.4.0, kaggle 2.2.4, torch
    2.13.0/torchvision 0.28.0); plugin.toml + ui.html confirmed inside
    the wheel. Caveats that stand regardless: PyPI torch on Windows is
    CPU-only (`UV_TORCH_BACKEND=auto` at provision time stays the
    documented GPU path), and the `[kaggle]` extra floats
    3lc-ultralytics (resolves 0.4.0 today). Re-run this check whenever
    the dependency set or the pin window changes — it is the wheel
    option's viability gate.
  - **Host-generation / SDK-pin skew** (added 2026-08-31; a CLASS, not a
    one-off — and the highest-value CI candidate yet). What happened:
    every test, the 80-test suite, the cold rehearsal, and three days of
    browser verification ran against 3lc-compute 0.2.1 (SDK contract
    0.1) while the fleet moved to 0.6/1.0.x (contract 0.3, pinned
    `plugin-sdk>=0.3.1,<0.4`) — and nothing checked that our
    `3lc-compute-plugin-sdk>=0.1.0,<0.2.0` pin intersects any host
    anyone actually runs. Two silent aggravators: 3lc-compute >=0.6
    ships `DEFAULT_PLUGIN_INDEX_URLS = ()` (PyPI-only provisioning,
    where the SDK starts at 0.2.2 — our 0.1 pin is UNRESOLVABLE there),
    and the branch name `port/0.2.x` reads as "ported" while the pin
    said `<0.2.0`. What would have caught it, cheapest first:
    1. **Pin-vs-fleet check in PRETAG** (zero infra): one line —
       resolve `3lc-compute` latest from PyPI, read its plugin-sdk pin
       (`pypi.org/pypi/3lc-compute/json`), fail if our pin's
       major.minor window doesn't intersect it. Same query this audit
       used.
    2. **A resolution canary in pytest** (small): `uv pip compile`
       (or `--dry-run` install) of `.[kaggle]` against **PyPI only**
       — catches "pin unresolvable on a PyPI-only host" without any
       host install.
    3. **The real CI shape** (the candidate worth building): a matrix
       job that provisions the plugin venv and boots
       `python -m tlc_plugin_sdk.worker` against BOTH the pinned dev
       host generation and the current public 3lc-compute release,
       then curls /health (assert `sdk_version` major.minor matches
       the host's pin window) + one custom route. The 2026-08-31
       scratch-venv smoke (health/ui/config/validate against SDK
       0.3.2) is exactly this job's body, hand-run.

## Rejected (restraint is part of the demo)

- **Sounds / completion chimes** — a data tool, not a game.
- **Confetti or celebration animation beyond the checkmark draw** — the
  playbook allows one celebration beat per tab; more is noise.
- **Theming toggles** — the Hub owns theme; the fragment inherits.
- **Onboarding tour / coach marks** — the gated flows ARE the guidance;
  a tour admits the UI failed to explain itself.
- **Extra motion (parallax, springs, skeleton shimmer)** — motion is
  information; nothing here informs.
- **WebSocket/event push for job progress** — polling with the guard is
  simple, restart-safe, and fast enough at these job counts.
- **Client-side charting library for history trends** — the sparkline
  pattern covers trend-at-a-glance; a chart belongs in the Dashboard.
