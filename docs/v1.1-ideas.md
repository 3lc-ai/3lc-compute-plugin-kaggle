# v1.1 ideas — rejected or deferred from v1

One line of reasoning each. Nothing here blocks the v1 freeze; revisit
after the demo.

## Deferred (worth doing)

- **File-browse endpoint** (server-side directory picker for the Import
  YAML path) — needs a new route (restart) and a filesystem-browsing
  security story; copy-paste with path tolerance covers the demo.
- **Recent-paths dropdown** on the YAML field — wants the file-browse
  UX decided first so the two don't fight over the same affordance.
- **Public-launch verification sweep** — the LAUNCH-VERIFY markers:
  submissions-used-today counter, daily-limit error classification,
  Kaggle-live success path all need one pass against the public
  competition. Added for launch (2026-08-04):
  - **sdist scope before any public artifact** — hatchling's default sdist
    ships the whole repo tree: CLAUDE.md/CONTEXT.md (internal protocol),
    docs/deployment-guide.md (real dev-machine paths), design-notes,
    ideas files. Harmless while distribution = the private repo testers
    already read (v1.2.4 audit, 2026-08-12: wheel itself is clean), but
    before the repo goes public or a wheel/sdist is ever published to an
    index, add `[tool.hatch.build.targets.sdist]` includes (src/ + README
    + tester docs only) or scrub those files;
  - **public slug is typo-free** — the swap-at-launch constant
    (`predictor.COMPETITION_SLUG`) must carry the real public slug, with
    "3lc" **unhyphenated** (the private test slug's `the-3-lc-...` +
    `comepetition` typos must not survive into the public one);
  - **RETIRED_SLUGS grows the test slug at swap time** — add the typo'd
    test slug to `predictor.RETIRED_SLUGS` **in the same commit** that
    swaps `COMPETITION_SLUG`, so a persisted v1.2.5-era slug (or any
    install that skipped v1.2.6's session migration) collapses to
    tracking the new constant instead of submitting to the retired test
    competition; verified by `tests/test_slug_swap.py` (added v1.2.6 —
    an inline comment alone is the same deferred-assumption failure mode
    that produced DP-04);
  - **probe/join recheck for non-host users** — Gudbrand's round-1
    submit-500: verify on the public competition that a not-joined user
    gets the friendly not_joined state from the GetCompetition pre-probe,
    never a raw Kaggle 500 (and that the probe's user_has_entered flips
    correctly after joining);
  - **catalog id cutover done** — gist + repo `catalog.json` both serve
    only `kaggle-exdark` (no stale `kaggle` entry resurrectable by a
    cached catalog).

## Rejected (restraint is part of the demo)

- **Sounds / completion chimes** — a data tool, not a game.
- **Confetti or celebration animation beyond the checkmark draw** — the
  playbook allows one celebration beat per tab; more is noise.
- **Theming toggles** — the Hub owns theme; the fragment inherits.
- **Onboarding tour / coach marks** — the gated flows ARE the guidance;
  a tour admits the UI failed to explain itself.
- **Extra motion (parallax, springs, skeleton shimmer)** — motion is
  information; nothing here informs.
- **WebSocket/event push for job progress** — polling with the guard is
  simple, restart-safe, and fast enough at these job counts.
- **Client-side charting library for history trends** — the sparkline
  pattern covers trend-at-a-glance; a chart belongs in the Dashboard.
